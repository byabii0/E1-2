# 프로젝트 개요

📌한 줄 요약

파이썬 객체 지향 문법과 JSON 데이터 관리를 활용해 실전 프로그램을 완성하고, Git으로 개발 전 과정을 기록하며 협업 역량의 기초를 다집니다.

🎯 학습 목표

 파이썬의 객체 지향 프로그래밍(OOP)과 JSON 데이터 관리를 활용해 터미널 기반 퀴즈 게임을 처음부터 끝까지 직접 설계 및 구현함으로써, 단순 문법 지식을 실전 프로그램 완성 능력으로 전환하는 것입니다. 이 과정에서 Git의 브랜치 전략과 버전 관리 프로세스를 체계적으로 경험하여 프로그램의 동작 원리를 깊이 이해하고, 향후 팀 협업을 위한 기술적 토대와 데이터 영속성에 대한 감각을 익힙니다.

✅ 미션 완료 체크리스트

**Python 기초**

- [ ] 변수가 무엇이고, 왜 사용하는지 설명할 수 있다.
      
      변수: 데이터에 이름을 붙여 저장합니다. 데이터를 재사용하고, 코드의 의미를 쉽게 파악하기 위해 사용합니다.
      
- [ ] int, str, bool, list, dict의 차이를 설명할 수 있다.

      int: 정수 (1, 100)
      str: 문자열 ("Hello")
      bool: 참/거짓 (True, False)
      list: 순서가 있는 목록 ([1, 2, 3])
      dict: 키-값 쌍으로 이루어진 사전 ({"name": "AI"})
      
- [ ] if/elif/else로 조건에 따라 다른 동작을 수행할 수 있다.

      if: 만약 ~라면(조건) 결과입니다.
      elseif: 조건이 여러개일 때 사용합니다.
      else: 어떤 조건에도 해당하지 않을 때 사용합니다.

      예시

       score = 85
           
      if score >= 90:
          print("A학점입니다!")  # 조건이 참(True)일 때 실행
      elif score >= 80:
          print("B학점입니다!")  # 위 조건이 거짓이고, 이 조건이 참일 때 실행
      else:
          print("C학점 이하입니다.") # 모든 조건이 거짓일 때 실행

**비교 연산자와 논리 연산자**

      비교 연산자: ==(같다), != (다르다), > (크다), < (작다), >= (크거나 같다), <= (작거나 같다)
      논리 연산자: and: 두 조건이 모두 참일 때, or: 두 조건 중 하나라도 참일 때, not: 조건을 반대로 뒤집을 때 (True -> False)

**주의해야 할 규칙**

      콜론(:): if, elif, else 줄 끝에는 반드시 콜론을 붙여야 합니다.
      들여쓰기(Indentation): 조건문 안에서 실행될 코드는 반드시 한 탭(또는 공백 4칸)을 들여써야 합니다. 파이썬은 들여쓰기로 코드의 범위를 구분하기 때문입니다.
      
- [ ] for와 while의 차이를 설명하고 적절히 선택할 수 있다.

      for, while은 반복문입니다.
      for: 정해진 횟수나 리스트의 요소만큼 반복할 때(예: 리스트의 모든 아이템 출력) 사용합니다.
      while: 특정 조건이 참인 동안 계속 반복할 때(예: 사용자가 '종료'를 입력할 때까지) 사용합니다.
      
- [ ] 함수를 정의하고, 매개변수와 반환값을 활용할 수 있다.

      반복되는 코드를 하나로 묶은 기능 단위입니다. 매개변수로 재료를 받고, 반환값(return)으로 결과를 내보냅니다.
      일반 변수는 필요할 때 코드 아무 곳에서나 만들어서 쓸 수 있지만, 매개변수는 함수 내부에서만 사용 가능합니다.
      반환값은 함수가 모든 작업을 마친 후 호출한 자리로 돌아오는 결과값입니다.

      예시

      def plus(a, b):
          return a + b
      
      # 1. 처음 코드
      result = plus(1, 2) 
      
      # 2. 함수가 실행된 후 (반환값이 '호출한 자리'로 돌아옴)
      result = 3 

**클래스와 객체**

- [ ] 클래스가 무엇이고, 왜 사용하는지 설명할 수 있다.

      클래스: 객체를 만들기 위한 설계도입니다. 관련된 데이터와 기능을 하나로 묶어 관리하기 위해 사용합니다.
      객체: 설계도를 보고 실제로 만든 실체입니다.

      단순한 기능 구현을 넘어, 유지보수가 쉽고 확장 가능한 구조를 만들기 위해 Quiz와 QuizGame을 클래스로 설계하였습니다.
      추상화: 내부의 복잡한 구현은 숨기고 사용자에게 필요한 기능만 노출하는 것입니다.
      재사용성: 클래스는 독립적인 부품과 같아서 다른 곳에서 다시 사용하기 용이합니다.

- [ ] __ init __ 메서드와 self의 역할을 설명할 수 있다.

      __init__: 객체가 생성될 때 자동으로 실행되는 초기화 함수입니다.
      self: "나 자신"을 가리킵니다. 클래스 내부에서 자기 자신의 변수나 메서드에 접근할 때 사용합니다.

- [ ] 클래스의 속성(attribute)과 메서드(method)를 정의하고 활용할 수 있다.

      속성(Attribute): 객체가 가지고 있는 정보(변수)입니다.
      메서드(Method): 객체가 할 수 있는 동작(함수)입니다. 

**파일 입출력**

- [ ] 파일을 열고, 읽고, 쓰는 기본 과정을 설명할 수 있다.

      open()으로 파일을 열고, read/write로 내용을 읽거나 쓴 뒤, 반드시 close()로 닫아줘야 합니다. (파이썬의 with문을 쓰면 자동으로 닫힙니다.)

- [ ] JSON 형식이 무엇이고, 왜 데이터 저장에 사용하는지 설명할 수 있다.

      데이터를 저장하는 표준 형식입니다. 텍스트 형태라 사람이 읽기 쉽고, 파이썬의 dict와 구조가 비슷해 프로그램 간 데이터 교환에 유리합니다.

- [ ] try/except를 사용하여 오류를 처리할 수 있다.

      예외 처리(try/except): 프로그램 실행 중 발생할 수 있는 에러(파일 없음, 숫자 입력 오류 등)를 미리 대비하여 프로그램이 갑자기 꺼지지 않게 막아줍니다.

**Git 기초**

- [ ] Git이 무엇이고 왜 필요한지 설명할 수 있다.

      Git: 코드의 변경 이력을 관리하는 도구입니다. 실수했을 때 과거로 되돌리거나, 여러 명이 협업할 때 필수입니다.

- [ ] init, add, commit, push, pull, checkout, clone이 각각 무엇을 하는지 설명할 수 있다.

      init: 현재 폴더를 Git이 관리하도록 시작합니다.
      add: 변경된 파일을 장바구니에 담습니다(Staging).
      commit: 장바구니에 담긴 변경사항을 기록으로 남깁니다(Snapshot).
      push: 로컬의 기록을 GitHub(원격)으로 올립니다.
      pull: GitHub의 최신 내용을 내 컴퓨터로 가져옵니다.
      checkout: 브랜치를 바꾸거나 과거로 이동합니다.
      clone: 원격 저장소를 통째로 내 컴퓨터에 복사해옵니다.

- [ ] 브랜치를 생성하고 병합할 수 있다.

      브랜치: 원본 코드를 건드리지 않고 새로운 기능만 따로 개발하는 독립된 공간입니다.
      병합(Merge): 브랜치에서 완성된 기능을 다시 메인 코드(main)에 합치는 과정입니다.

- [ ] 원격 저장소를 clone하고, pull로 변경사항을 가져올 수 있다.

      clone: 원격 저장소에 있는 프로젝트를 내 컴퓨터에 처음으로 내려받을 때 사용합니다. 새로운 폴더가 생깁니다.
      pull: 이미 내 컴퓨터에 저장소가 있는 상태에서, 원격 저장소에 새로 올라온 변경 사항만 내 컴퓨터로 합칠 때 사용합니다. 기존 폴더의 내용이 바뀝니다.


# 퀴즈 주제와 선정 이유

퀴즈 주제: 백상아리의 기본적인 생태 정보입니다.

선정 이유: 상어가 나오는 영화와 다큐멘터리를 좋아하기 때문입니다.

# 실행 방법

클래스: Quiz, QuizGame

Quiz 클래스는 하나의 퀴즈 정보를 담는 데이터 모델(Data Model) 역할을 수행합니다. 문제 내용(question), 사지선다 보기(choices), 그리고 정답 번호(answer)를 하나의 객체로 묶어 관리하며, 데이터의 구조를 정의하는 책임을 집니다.

QuizGame 클래스는 게임의 전체 흐름을 제어하는 컨트롤러(Controller) 역할을 수행합니다. state.json 파일을 통한 데이터의 영속성 관리(저장 및 불러오기), 사용자 메뉴 인터페이스 제공, 퀴즈 실행 로직 처리, 점수 계산 및 퀴즈 추가/목록 보기 등 프로그램의 핵심 비즈니스 로직을 총괄하는 책임을 집니다.

메서드: load_data(), save_data(), play_quiz(), add_quiz(), list_quizzes(), show_score()

load_data() : 데이터 불러오기
프로그램 실행 시 state.json 파일을 읽어와 저장된 퀴즈 목록과 플레이어의 점수를 메모리로 로드합니다. 파일이 없거나 손상된 경우, 기본 데이터셋을 생성하여 프로그램이 중단 없이 실행되도록 돕습니다.

save_data() : 데이터 저장하기
현재 메모리에 있는 퀴즈 목록과 누적 점수를 state.json 파일에 기록합니다. 퀴즈를 추가하거나 게임을 마친 후 호출되어 데이터의 영속성을 보장합니다.

play_quiz() : 게임 시작
등록된 퀴즈 중 하나를 무작위로 출제합니다. 사용자의 답변을 입력받아 정답 여부를 확인하고, 결과에 따라 점수를 부여한 뒤 화면에 피드백을 출력합니다.

add_quiz() : 새로운 퀴즈 추가
사용자로부터 질문, 보기(4개), 정답 번호를 입력받아 새로운 Quiz 객체를 생성합니다. 생성된 퀴즈를 전체 목록에 추가하고, 즉시 파일에 저장하여 영구 보관합니다.

list_quizzes() : 퀴즈 목록 조회
현재 시스템에 등록되어 있는 모든 퀴즈의 질문 내용을 번호와 함께 리스트 형태로 보여줍니다.

show_score() : 누적 점수 확인
플레이어가 지금까지 퀴즈를 맞혀 획득한 전체 누적 점수를 화면에 표시합니다.

# 메뉴 기능 목록

퀴즈 풀기, 퀴즈 추가, 퀴즈 목록 보기, 현재 점수 확인, 종료 기능이 있습니다. 한 문제를 맞힐 때마다 10점씩 추가됩니다. 퀴즈를 종료해도 점수는 누적됩니다. 1-5 사이의 숫자를 입력하여 각 기능을 실행할 수 있습니다. 기본 퀴즈의 개수는 5개입니다.

# 파일 구조

my_quiz_project/: 최상위 프로젝트 폴더

main.py: 파이썬 실행 코드 파일

state.json: 퀴즈 데이터 및 점수가 자동 저장되는 파일

.gitignore: Git이 무시할 파일 목록을 적어두는 텍스트 파일입니다. 이 파일에 적힌 파일이나 폴더는 Git이 추적하지 않으므로, GitHub 같은 원격 저장소에 올라가지 않습니다. 보안(비밀번호, API 키, 개인정보가 담긴 설정 파일), 불필요한 파일(프로그램 실행 시 자동으로 생성되는 임시 파일이나 캐시 파일(__pycache__/), 용량 관리(venv/: 파이썬 가상환경), 운영체제 차이(Mac의 .DS_store, Windows의 썸네일 파일 등) 등의 특정 파일들을 제외해야 합니다.

키      타입                 설명

대량 데이터 대처 방안 및 최적화 전략

메모리(RAM) 관점: 파이썬 리스트 구조상 10,000개의 데이터도 약 3.5MB 수준에 불과하므로, 일반적인 PC/서버 환경에서는 메모리 병목 현상이 발생하지 않습니다.

검색 및 접근 속도 관점: 퀴즈 목록 조회 및 정답 확인 시 list 인덱싱을 활용하므로 시간 복잡도는 $O(1)$을 유지하여 데이터가 늘어나도 즉각적인 응답이 가능합니다.

향후 확장성(100,000개 이상 데이터 확장 시): 데이터가 10만 개 이상으로 커져 JSON 파싱 시간이 수백 ms 이상 지연될 경우, JSON 전체를 파일로 덮어쓰는 대신 SQLite DB 또는 PostgreSQL과 같은 관계형 데이터베이스(RDBMS)를 도입하여 페이징(Paging) 처리하는 구조로 최적화할 수 있습니다.

.json은 JavaScript Object Notation의 약자로, 데이터를 저장하고 주고받을 때 사용하는 표준 텍스트 형식을 의미합니다. 텍스트 파일 형태이므로 메모장으로 열어도 사람이 직접 내용을 확인하고 수정하기 쉽습니다.

파일 역할: 퀴즈 데이터(문제, 보기, 정답)와 플레이어의 누적 점수를 프로그램 종료 후에도 영구적으로 유지하는 데이터 보존(영속성) 파일입니다.

state.json 파일은 프로그램의 핵심 데이터를 담고 있으므로, 파일 손상이나 유실에 대비하여 다음과 같은 복구 프로세스를 가집니다.

1. 자동 백업 전략 (Backup)

시점: 데이터를 성공적으로 저장할 때마다 기존의 정상적인 파일을 state.json.bak으로 복사하여 백업본을 유지합니다.
목적: 저장 중 갑작스러운 전원 차단이나 오류로 인해 메인 파일이 깨질 경우를 대비합니다.

QuizGame 프로그램은 state.json 파일 입출력 과정에서 발생할 수 있는 파일 시스템 권한 오류(Permission Error)에 대응하는 예외 처리 로직과 사용자 안내 기능을 갖추고 있습니다. 파일이 읽기 전용으로 설정되어 있거나 시스템 권한 문제로 접근이 거부될 경우, save_data() 및 load_data() 내부의 try-except 구문이 PermissionError를 포착하여 프로그램의 비정상 종료를 방지합니다. 이때 터미널에는 "파일에 대한 쓰기 권한이 없습니다. 파일 권한을 확인해 주세요"와 같은 직관적인 안내 메시지가 출력되어 사용자에게 오류 상황을 명확히 알립니다.

권한 문제로 데이터 저장이 실패할 경우 Operating System 환경에 맞춰 다음과 같은 절차로 권한을 복구할 수 있습니다. Linux 및 WSL 환경에서는 터미널에서 ls -l state.json 명령어로 현재 권한을 확인한 후, chmod 664 state.json을 실행해 읽기/쓰기 권한을 부여하거나 sudo chown $USER:$USER state.json으로 소유권을 변경합니다. Windows 환경에서는 state.json 파일의 우클릭 속성 창에서 '읽기 전용' 체크를 해제하거나, [보안] 탭의 [편집] 메뉴에서 현재 계정에 '수정' 및 '쓰기' 권한을 허용하여 문제를 해결할 수 있습니다.

2. 단계별 복구 프로세스 (Recovery Workflow)

파일 로드 시 오류(파일 없음, JSON 형식 깨짐 등)가 발생하면 시스템은 아래 순서로 자동 복구를 시도합니다.
[1단계] 메인 파일 로드: state.json 읽기 시도.
[2단계] 백업 파일 전환: 1단계 실패 시, state.json.bak 파일이 존재하는지 확인하고 이를 메인 데이터로 승격시켜 로드합니다.
[3단계] 시스템 초기화: 백업 파일조차 없거나 손상된 경우, 프로그램은 중단되지 않고 **'기본 퀴즈 데이터셋'**을 메모리에 생성하여 새로운 state.json을 구성합니다.

3. 수동 복구 방법 (Manual Reset)

만약 데이터가 회생 불가능하게 왜곡되었다면, 사용자는 다음 방법을 통해 시스템을 초기 상태로 되돌릴 수 있습니다.
방법: 실행 경로에 있는 state.json과 state.json.bak 파일을 삭제한 후 프로그램을 재실행합니다. 프로그램은 자동으로 기본 설정 파일을 재생성합니다.


인코딩: UTF-8 (표준 인코딩 지원, 한글(퀴즈 질문, 보기)이 깨지지 않고 안정적으로 보존됩니다.)

# 공통 입력/예외 처리 기준(최소 요구)

**공통 입력 요소**

입력 항목 ㅣ 입력되는 위치 ㅣ 데이터 형식
   
메뉴 번호 ㅣ 메인 메뉴 화면 (choice) ㅣ 문자열 (str)
   
정답 번호 ㅣ 퀴즈 풀기 화면 (ans) ㅣ 정수형 (int)
   
새 문제/보기 ㅣ "퀴즈 추가 화면 (q, c)" ㅣ 문자열 (str)
   
새 정답 번호 ㅣ 퀴즈 추가 화면 (a) ㅣ 정수형 (int)

**공통 입력 처리 기준**

모든 입력은 터미널 콘솔의 input() 함수를 통해 받으며, 입력받은 데이터를 처리할 때 아래 3가지 규칙을 공통으로 적용합니다.
   
문자열 입력 받기 (input()): 사용자로부터 텍스트 입력을 받아 변수에 저장합니다.
   
타입 변환 및 예외 검사 (int()): 정답 번호나 메뉴 입력 시 숫자로 변환하며, 문자 입력 시 에러가 나지 않도록 try-except로 감쌉니다.
   
입력값 범위 검증 (Validation): 정답 번호는 1번-4번 범위 내인지, 메뉴 번호는 1번-5번 범위 내인지 검사합니다.

**예외 입력 요소**

예외 입력 요소 ㅣ 발생 위치 ㅣ 사용자의 예외 입력 행동 ㅣ 발생할 수 있는 에러/문제점
   
문자/특수문자 입력 ㅣ "play_quiz, add_quiz (정답 번호 입력 시)" ㅣ 숫자가 필요한 곳에 "abc", "#" 등 입력 ㅣ int() 변환 실패로 ValueError 발생하여 프로그램 강제 종료
   
범위 밖의 숫자 입력 ㅣ "play_quiz, add_quiz, 메뉴 선택" ㅣ 보기가 1-4번인데 0, 5, -1 등 입력 ㅣ 존재하지 않는 정답 처리 또는 논리적 오류 발생
   
공백/빈 문자열 입력 ㅣ 모든 input() 창 ㅣ 아무것도 입력하지 않고 Enter만 입력 ㅣ 문제 내용이나 보기가 빈 값("""")으로 저장됨
   
메뉴 입력 오류 ㅣ 메인 메뉴 (choice) ㅣ 1-5번 이외의 문자/숫자 입력 ㅣ 잘못된 메뉴 선택으로 인한 오작동

**예외 입력 처리 기준**

try-except: 숫자가 필요한 입력창에 문자나 특수문자가 들어올 경우 ValueError를 포착하여 프로그램의 강제 종료를 방지합니다.

1 <= ans <= 4 조건식: 메뉴 선택이나 정답 입력 시에 사용하여 사용자가 정해진 선택 범위 내의 숫자만 입력하도록 검증합니다.

모든 입력창에서 아무 내용 없이 Enter만 입력하여 빈 값이 저장되는 것을 방지하기 위해, 입력값의 존재 여부를 검사하고 내용이 없을 경우 안내 메시지와 함께 재입력을 요구한다.
